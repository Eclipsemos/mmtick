## 信号参数

| 参数 | 值 |
|---|---:|
| 方向 | 仅做多，禁止非减仓开空 |
| K 线周期 | 15 分钟 |
| 预热 | 最近 200 根官方 K 线 |
| ATR | Wilder ATR(32) |
| ATR 跟踪倍数 | 3.0 |
| 趋势效率 | 8 根，最低 0.25 |
| 反向确认 | 0.0 ATR；仅做多路径不反手 |
| 动作锁 | 每根 15 分钟 K 线最多一次策略动作 |
| 盈利保护 | 关闭（0.0/0.0 ATR） |
| 延续重入 | 关闭（0.0 ATR） |

ATR 上穿且趋势效率通过时开多；持有多仓后，下穿只发送 `reduce_only` 平多。平仓后保持空仓，
等待下一次有效上穿。趋势过滤只限制开仓，不阻止已有多仓退出。

## 风险与成交

| 参数 | 值 |
|---|---:|
| 杠杆/保证金 | 2x isolated |
| 持仓模式 | Hedge |
| 仓位比例 | 62.5% 权益 |
| 目标名义敞口 | 1.25x 权益 |
| 固定下单上限 | 关闭（0） |
| 单日亏损/订单数上限 | 关闭（0/0） |
| 开仓盘口偏离上限 | 30 bps |

实盘采用 Binance 返回的订单和成交，不应用 paper 的 5/2 bps 固定成本。订单还必须通过凭证、
启动确认、IP 白名单、Futures 权限、2x isolated、Hedge 模式、测试订单、账户对账、持久停止状态、
既有空仓和待处理订单等门禁。Git 中开关为启用不等于运行时必然可下单。

## 初始化与状态

实盘启动先用最近 200 根官方 K 线构造指标，再恢复 `live_strategy_state`。随后代码强制将
`startup_alignment_checked` 设为真，所以首次启动、重启或参数迁移都不会按当前趋势追入，
只处理之后发生的新鲜穿越。

这与 long-only paper 的一次启动趋势对齐不同，也是相同信号参数可能产生不同第一笔交易的
主要原因。实盘 ATR 退出由服务收到 Tick 后触发，不是 Binance 托管止损；服务、网络或行情
中断会造成执行风险。
